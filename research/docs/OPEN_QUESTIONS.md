## 2. Какие ML-задачи СЕЙЧАС невозможно выполнить (полностью)

| Задача | Почему невозможно | Что можно вместо этого |
|---|---|---|
| **«Несанкционированный доступ»** (обученная модель) | Нет ground-truth: нет журналов допусков, СКУД, решений диспетчера, камер — невозможно разметить «реальное проникновение». Без положительного класса supervised-модель не построить. | Unsupervised anomaly detection на КД/движениях (выбросы по времени/маршрутам) как **прототип**, без гарантии метрик. |
| **«Пожарный риск»** (полный вариант) | Нет графиков сварочных/горячих работ (АРМ-Контроль) — главного триггера по ТЗ. Без корреляции с работами задача «раннее предупреждение на основе работ» невыполнима. | Модель по динамике дыма/температуры (без фактора работ) — частичная, с пометкой ограничения. |
| **«Износ инфраструктуры»** | Нет визуальных обследований ОЭ (целевая метка), нет возраста оборудования, нет фондов по районам. Без возраста/обследований нет ни признаков, ни метки «нужен ремонт». | Косвенные признаки наработки насосов/вентиляторов (счётчики включений) — только эвристика. |
| **«Отказ датчика»** (официальная метка) | Формальное определение отказа не дано (вопросы 1–3). Прокси «Неисправен/Обесточен» есть, но не факт что совпадает с пониманием заказчика. | Baseline на прокси-метке статусов — возможен, но требует валидации/уточнения. |
| **Интерактивная карта объектов** (раздел 10 ТЗ) | Нет геоданных (координат) ни у объектов, ни у каналов; нет связи канал↔объект. GeoJSON/WKT построить не из чего. | Схема-«граф» PК по коллекторам (`p1/p3`) как замена карты в прототипе. |

## 3. Что реально выполнимо уже сейчас (для первых демо)

1. **«Отказ датчика»** (прокси-метка по статусам «Неисправен/Обесточен»): фичи → LightGBM, цель «отказ в +24ч». Это единственная задача, у которой можно показать полноценные Precision/Recall на наших данных (с оговоркой про метку).
2. **Пожарный риск (частичный)**: по динамике дыма/температуры без фактора работ.
3. **Несанкц. доступ**: unsupervised-прототип (аномалии движения/КД).
4. **Продуктовый каркас** (дашборд, журнал прогнозов) — на прогнозах «Отказ датчика».

## 4. Рекомендации (что уточнить в первую очередь)

1. **Формальное определение отказа датчика** и журнал ОДС (метка) — без этого страдает «Отказ», главная выполнимая задача.
2. **Геоданные / маппинг канал↔объект** — без этого невозможна карта и объектные агрегации (доступ, износ).
3. **Данные АРМ-Контроль (горячие работы, допуски)** — разблокируют пожарный риск и доступ.
4. **Протокол оценки** (скрытый тест? метрика? горизонт) — определяет наш пайплайн валидации.
