# BACKLOG: нереализованное, отложенное и блокеры

Дата: 20.09.2026. Источники: `ML_PLAN.md`, `OPEN_QUESTIONS.md`, `ADAPTERS_README.md`, фазы MVP.
Формат: `[P0/P1/P2]` — приоритет; P0 — до релиза, P1 — первая итерация, P2 — требует внешних данных.

## 1. ML — не реализовано / отложено

**fire**
- [P1] Шум-паттерны ИПР (пары срабатываний в 1–5 мин), отдельный приоритет «ручной извещатель» vs «подтверждённый дым» — статистика есть, колонок в панели нет.
- [P1] Валидация «серьёзной тревоги» на кампаниях 2021W17-23/2026W23 (частично проверено, §21.7 в ML_PLAN Часть II).
- [P2] Value-тренды температуры 7д у объекта (текущий вариант 6ч-агрегатов — отрицательный результат).

**sensor**
- [P1] Полная per-type линейка (газ/КД/движение/температура) — начат только «Датчик дыма» (PR24 ×5); требует цикла ретрейнов и пересмотра инференс-контракта.
- [P1] Интеграция подтверждённых фич (эхо 30–60 мин, «дверь→движение ≤1 мин», night/weekend-флаги) в панель + ретрейн.
- [P1] Value-тренды деградации (числовых рядов мало; для насосов их нет вовсе).

**access**
- [P1] Sequential-фичи расширить до 5–15 мин, time-of-day/weekend baseline, объект×день аномалии (z/IF).
- [P2] Связь со СКУД/допусками — отличать проникновение от теста/обслуживания (нет данных).

**wear / слой 2 (survival)**
- [P1] Калибровка S(t) (isotonic per-bin), конформальные интервалы «дней до события».
- [P1] Регулярная сетка точек прогноза + по-запросный `extract_features(channel, t)` для real-time.
- [P1] Эмпирический фон риска (train-only), гибрид per-object (0.5·лок + 0.5·глоб) для объектов с ≥30 каналами.
- [P1] Горизонт 90д (реализован в research, PR-AUC 0.983) — довести до инференс-контракта/сервиса.

**Общее (ML)**
- [P1] L2-агрегация на уровень объекта: индекс риска (правила v1 → бустинг поверх L1).
- [P1] Model cards по задачам (ограничения ground-truth, device CPU/GPU ±0.02 PR-AUC).
- [P1] Регулярный drift-пересчёт (нужны свежие данные): процентили p24/risk30 + O/E.
- [P2] Адаптеры внешних данных (АРМ-Контроль/ОДС/СКУД/реестр) — интерфейсы готовы, данных нет.

## 3. Блокеры: ждём данные/решения заказчика

| Что нужно | Для чего | Статус |
|---|---|---|
| СКУД / журналы допусков | access: ground-truth «проникновение vs обслуживание» | ❌ нет |
| Журнал ОДС / история ремонтов | sensor: истинная метка отказа; «дней до отказа после ремонта» | ⚠ HelpDesk без интеграции событие→заявка |
| АРМ-Контроль (сварочные/горячие работы) | fire: главный триггер по ТЗ; очистка таргета | ❌ нет |
| Реестр оборудования (возраст, ремонты) | wear: возраст + наработка как фичи | ⚠ возраст/норматив есть, история частичных ремонтов не ведётся |
| Маппинг «Объект N» ↔ `ид_объект` | графики ТО/ППР 2026 → per-object маскировка и модуль заявок | ❌ нет |
| Формальное определение «отказ» | sensor: уточнить прокси-метку | ❌ нет ответа |
| Протокол оценки (скрытый тест?, метрика, горизонт) | пайплайн валидации под лидерборд | ❌ нет ответа |
| Гео-координаты (GeoJSON/WKT) | точная карта | ❌ в данных нет (карта схематичная) |
