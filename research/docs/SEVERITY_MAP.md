# SEVERITY_MAP — последствия для RBAM-приоритета (без реестра)

Версия: 0.1 · Дата: 20.09.2026 · Статус: принята как эвристика v1 (заменится
реестром оборудования/возрастом при получении данных P2)

## Зачем

Приоритет профилактики = **вероятность события × последствие**. Вероятность даёт
TTE-слой (risk30, exp_days). Последствие в данных отсутствует (нет реестра) —
оцениваем **эвристикой** по типу канала/системы и объекту (по протоколу экспертов
16.09: «отказ — цепочка», «доступ — последовательность», «подтопление — характерный
сценарий»).

## Шкала и веса (0..1)

| Класс | Типы каналов (тип_датчика) | severity | Обоснование |
|---|---|---|---|

## Вес объекта (modifier)

Без реестра объектов используем **размер объекта** как прокси масштаба:
число активных каналов объекта за период (`каналов_активных_об_б_сум_30д` из панели).
- ≤ 5 каналов: 1.0 (типовой пикет),
- 6–20: 1.25 (узел),
- > 20: 1.5 (крупный узел/хаб с подчинёнными системами).

## Формула приоритета

```
score = risk30_cal (или risk30 raw) × severity(тип) × scale(объект)
приоритет = сорт. по score desc → топ-K / план
exp_days используется как «желаемый горизонт»: exp_days < 7 → текущий квартал,
7–21 → следующий, > 21 → плановый год (мягкие границы).
```

Примечание: severity/scale — единый конфиг `research/inference_contract.py`
(SeverityConfig). При получении реестра (возраст, истории ремонтов, назначение)
заменяется такими же колонками без переобучения моделей.
