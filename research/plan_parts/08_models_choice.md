## 8. Выбор моделей (по уровням)

### Контекст, влияющий на выбор
- Целевой класс **редкий**: доля тревог в чистых неделях 0.2–0.5% (медиана 0.34%), в кампаниях — до 17.7%. → нужны дизбаланс-устойчивые алгоритмы + классовая взвешивание + подбор порога по PR-кривой, а не по accuracy.
- Признаки — **агрегаты** (счёты/доли/скользящие статистики), частично категориальные (тип, коллектор, ПК), много пропусков («канал молчал» = окно без событий) → градиентный бустинг как базовый класс подходит лучше, чем гладкие нелинейки вроде MLP (нет надобности в топологии).
- Горизонт 24ч, инференс < 5 мин на объект — табличный ML с предпосчитанными фичами легко укладывается.

### L1 — главные модели по типам датчиков

| Алгоритм | Плюсы | Минусы | Решение |
|---|---|---|---|
| **LightGBM** | быстрый, справляется с пропусками (`NaN` как «нет событий»), category-фичи, `is_unbalance`/`scale_pos_weight`, калибровка простая | переобучение на малых типах | ✅ **базовый** для всех типов |
| **CatBoost** | силён на категориальных + дизбаланс, OrderedBoost | медленнее, странна на больших датасетах | ✅ сравнить на типах с богатой категориальной структурой (Дым, КД) |
| XGBoost | зрелый, но категориальные требует кодировки | — | резерв |

**Пакет для каждого типа (кратко):**
1. **Глобальная по типу**: LightGBM (по умолчанию) + CatBoost (кандидат сравнения) → выбираем по валидационной PR-AUC/Precision-Recall.
2. **Локальная по объекту** (если N≥30 каналов): LightGBM малого размера (max_depth 3–4, сильная регуляризация) ИЛИ, для очень малых групп — LogisticRegression на нормализованных фичах (устойчивее к переобучению). Стек 0.7·global + 0.3·local.
3. **Калибровка**: IsotonicRegression на out-of-fold вероятностях **per тип** (с учётom распределения порогов). При малых выборках — Platt scaling.
4. **Порог**: выбирается по PR-кривой под целевые Precision ≥ 0.7 / Recall ≥ 0.5, с допуском по обоим.

### L2 — агрегация на уровень объекта (дашборд)

| Подход | Когда | Оценка |
|---|---|---|
| Правила: max/сумма топ-k канальных рисков | для старта, интерпретируемо | ✅ v1 |
| Логистическая регрессия на перцентилях канальных рисков объекта | когда правил не хватит | ⚠ после правила |
| Лёгкий LightGBM на «свёртке» канальных рисков | конечная цель | 🔜 поэтапно |

Правила L2 проще: `index_object = w1*max(canal_risks) + w2*top3_mean(risks) + w3*тревога_за_24ч`, пороги — экспертные, калибровка не нужна.

### Сравнение альтернатив (зачем не LSTM/Transformer/Prophet)

| Модель | Почему НЕ берём в основной контур |
|---|---|
| LSTM/GRU/Transformer (TFT) | Требует авторегрессионную цель на сыром ряду; при нашем объёме (11.5k каналов × часы) и почти-бинарном сигнале выигрыш над LGBM фичами мал, рисков переобучения больше, интерпретируемость хуже. |
| Prophet/сезонная декомпозиция | Это тренды одного ряда без ковариат; у нас много ковариат (типы, соседи, кампании) — бустинг их использует лучше. |
| «Дальний» ансамбль (GBM + DNN) | Оправдан только если LGBM-CV покажет потолок; дорого. |

**Ограничение метода (важно для бэкенда):** бустинг даёт **вероятность**, а не «когда именно» +24ч. Горизонт 24ч — это скалярная цель «событие в следующие 24h», модель не выдаёт распределение времени. Если потребуется «в какое время» — отдельная задача (multi-horizon/временной point process) — вне v1.

### Метрики и протокол сравнения
- Основные: **PR-AUC**, Precision@Recall≥0.5, Recall@Precision≥0.7, калибровка (ECE/изотonic fit), PR-кривая на тесте 2026 с исключением кампаний.
- Сплит: временной (train ≤ 2024, val = 2025, test = 2026); дополнительно — временной CV с шагом недели.
- Дизбаланс: `scale_pos_weight = neg/pos` (или class_weight), только на train; SMOTE — резерв для редких типов.
- Определяем «потолок» случайной модели и majority-class baseline для каждого типа.
