## 4. Пайплайн признаков

### 4.1. Агрегация в окна
События датчика → ежечасные агрегаты: счётчик событий, доля тревог, доля «шума» (0.00/0.01/смены состояния), доля неисправных статусов, средние/медианы значений. Окна: 6ч, 24ч, 7д, 30д + скользящие средние/std/тренд/мин/макс.

### 4.2. Пер-канальная нормализация
`z = (x - медиана_канала_90д) / (MAD_канала_90д + eps)`; «доля от фона» для частоты событий.

### 4.3. Статические
Тип датчика, инж. подсистема, коллектор `p1`, пикет `p3`, `p5` из тега; категории объекта; возраст (если появятся даты ввода); `ид_канала_данных` как категория (при достаточном объёме).

### 4.4. Контекст объекта
Признаки соседей по объекту (раздел 2.2) + флаги кампаний/плановых работ + час/день/сезон.

### 4.5. Горизонт и валидация
- Горизонт: **24 ч — дефолт**; допускаются 1/6/12/48ч и несколько горизонтов одновременно (реализовано в `09_wear_horizons`).
- Сплит: **временной** (train ≤ 2024, val = 2025, test = 2026), **кампании исключены** (`data_utils.filter_clean_weeks`).
- **2021 — переходный период** (несколько версий систем одновременно): исключать/нормализовать/добавлять признак переходного периода.
- Метрики: Precision ≥ 0.7, Recall ≥ 0.5 — стартовые значения по умолчанию (обоснованные отклонения допустимы); дополнительно PR-AUC, корригированные на базу (lift), калибровка (isotonic/logistic per type).
- Дефицит класса — только train-овский SMOTE/class_weight.
- Аномальные значения (−100/255/MAX) — коды производителя: обработка (удалять/NaN/флаг/оставить) фиксируется явно.
