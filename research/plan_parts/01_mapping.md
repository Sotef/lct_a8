# ML-план: архитектура моделей для прогнозирования аварий/отказов

Версия: 0.2 · Автор: ML Research Team · Статус: план (согласование)

## 1. Маппинг схемы «Приложения 1» на наши данные

Приложение 1 описывает live-схему СМВУ (журнал + реестры). Она отличается от выгрузок `.7z`, но легко маппится:

| Элемент Приложения 1 | Наши данные (выгрузки .7z / справочники) |
|---|---|
| Журнал: ИД записи журнала | `ид_события` |
| Журнал: ИД канала данных | `ид_канала_данных` |
| Журнал: ИД типа канала данных | в выгрузках колонки нет — тип берём из `справочник_каналов_датчиков.csv` (`тип_датчика`, `тип_инж_системы`) |
| Журнал: Текущее значение | `значение_датчика` |
| Журнал: Дата записи (одна колонка) | у нас `дата` + `время` (объединяем в timestamp) + флаг `тревожное` |
| Реестр каналов: Тег в дереве объектов (`МК-1.1.1.1.1.1`) | `тег_инженерной_системы` (формат `p1-p2.p3.p4.p5.`) — той же природы |
| Реестр типов каналов (2..12) | словарь: contact-unlock-norm=КД Дверь/КД АВ/КД Люк, switch=Переключатель, smoke=Датчик дыма, movement=Датчик движения, gas=Газовый датчик, pump=Состояние насоса, fan=Состояние вентилятора, phase=Состояние фазы, temperature=Датчик температуры/Тепловой датчик |
| Дерево объектов (`Административное здание К1, пожарная система`) | `справочник_объектов_диспетчер.csv` (district → controlHouse → guardObject) — аналогично |

**Что добавляет Приложение 1 (ценно):**
- **Тип канала как отдельная сущность** — подтверждает стратификацию моделей по типу датчика (у нас `тип_датчика`).
- **Диспетчерские названия типов** — семантика, которой нет в числах телеметрии.
- **Дерево объектов/инженерных систем** — готовый каркас признаков «объект/система» (пожарная система, вентиляция, камера, шкафы).

**Гипотезы для проверки на данных:** покрытие журналов реестром (уже проверено — 99.9%), стабильность id каналов (сменяются ли), один датчик ↔ один канал.

**Обновление по итогам встречи с экспертами (16.09):**
- **`ид_объект` подтверждён** — обновлённый справочник каналов содержит его; связь канал→объект восстановлена.
- Старый составной тег `тег_инженерной_системы` (`p1-p2.p3...`) возник при обезличивании — в решении его можно игнорировать, как основной ключ объекта использовать `ид_объект`.
- Гео-координаты не обязательны: схематичная линейная карта коллекторов + пикеты (`p3`, шаг 10 м — для демо можно другой).
