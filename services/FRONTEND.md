# FRONTEND — веб-интерфейс диспетчера ОДС

> Мобильная версия (адаптив + PWA: офлайн-очередь, фото, Web Push) — план реализации,
> оценки и чек-лист приёмки: `MOBILE_PLAN.md`.

Версия: 1.0 · `app/web` · vanilla JS (ES2020), без сборки, без зависимостей и CDN.
Раздаётся тем же FastAPI (`StaticFiles`), API-маршруты `/api/v1/*` имеют приоритет.

## Запуск

```powershell
cd services
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# открыть http://127.0.0.1:8000/  (демо-доступы есть на экране входа)
```

Каждый раздел — модуль `Views.<имя>` с методами `render(main, state, silent)` и
метаданными `name`/`icon`. `state` — общее состояние (`task`, `objFilter`,
`clock`, `navigate`, `setTask`), объект создаётся в `app.js`.

## Ключевые сценарии

1. **данные → прогноз → алерт → диспетчер → решение → результат**: прогнозы
   пересчитываются на каждом тике сим-времени; всплывает уведомление; диспетчер
   открывает карточку (`gauge`, вероятности, S(t), «когда ожидать», SHAP-факторы),
   принимает решение (подтвердить / отклонить / профилактика). «Профилактика»
   создаёт (или назначает уже открытую) заявку и видна в разделе «Заявки».
2. **Тренд риска** (`GET /meta/risk-history?measure=`): переключатель горизонта
   **1 день (P≤24 ч) / 3 дня (P≤72 ч) / 7 дней (из S(t)) / 30 дней (risk30)** и
   тумблер «максимум»; ось в процентах, подпись «сейчас». Для wear risk30 высок
   по природе модели — на коротких горизонтах картина информативнее.
2. **Заявки**: автоформирование на каждом тике, drag&drop смены статуса с
   серверной валидацией переходов, обязательный комментарий при закрытии,
   вся история — в журнале аудита.
3. **Аудит**: входы/неудачные входы, решения, заявки, админ-действия, ошибки
   интерфейса; у каждой записи есть ip и `request_id`, детали раскрываются в JSON.
4. **Диагностика**: «Система → Системный лог» — live-хвост лога сервиса по
   `after_id`, фильтры по уровню/логгеру/подстроке, пауза, выгрузка файла.
5. **Реплей и его скорость**: вкладка «Система → Обзор» показывает прогресс периода,
   темп (бакетов/час, длительность последнего тика) и даёт управление — «Заново
   с января», «Пауза/Продолжить», «Шаг +6 ч», уровни скорости **1×/2×/4×/8×**
   и тумблеры «быстрый расчёт (без SHAP-факторов)» / «параллельный расчёт задач»;
   по умолчанию включён автоцикл (`SIM_LOOP=1`).
6. **Объяснения по запросу**: в быстром режиме прокрута SHAP-факторы не считаются
   массово — в карточке прогноза есть кнопка «Рассчитать факторы» (≈1 с), результат
   сохраняется в прогнозе (`GET /forecasts/{id}/factors?compute=true`).

## Оговорки честности данных

- Координат объектов нет: карта **схематичная** (секторы районов, позиция по
  хешу id), в интерфейсе это прямо написано.
- **Риск объекта = P(событие ≤ 7 дней)** (`risk7d` из `GET /objects` и
  `GET /objects/graph`): максимум недельного прогноза по каналам за последние 3 суток
  сим-времени. Список объектов, карта-радар, граф систем, фильтры и сортировка
  работают с ним; месячный `risk30` L2-материализации остаётся в подсказках
  («L2 risk30 …») как исторический ориентир — так «не долбит» месячными значениями.
  Объекты без недельных прогнозов помечены «нет недельных прогнозов» и рисуются
  «полой» точкой, чужой риск не подставляется.
- Риски объектов (L2) — материализация из `l2_object_risk.parquet`, обновляется
  циклом прогноза; в карточке объекта они помечены как L2.
- Риск берётся как `risk30_cal`, если калибровка есть (access), иначе `risk30`
  (единая логика `UI.riskOf`).
- Активность направлений (бейдж «событие») — это `event_flag` прогноза, а не
  ручная пометка диспетчера.

## Живое обновление без мигания

- Раздел собирается в offscreen-фрагмент (`UI.stage()`) и попадает на экран одним
  вызовом `UI.mount()`: пока идут запросы, старая версия раздела остаётся видимой
  (раньше контейнер очищался заранее и страница «пропадала» на время загрузки).
- `merge: true` (тик сим-часов, смена направления, фильтры, пагинация) — обход
  дерева и обновление **только изменившихся узлов**: числа/статусы меняются на месте
  и мягко подсвечиваются (`.lv-flash`), карточки не пересобираются, фокус и скролл
  сохраняются. `merge: false` — атомарная замена (разделы «Система», «Аудит»,
  «Пользователи», граф систем, карта-радар).
- **Блоки, которые рисует код карточки, помечаются `data-keep`** (график тренда
  риска, график обслуживания, лента действий): морфинг их не трогает, поэтому
  прошлые данные остаются на экране, пока не придут новые — графика не «пропадает».
  Скелетон показывается только когда показывать нечего (узел пуст).
- Правило для новых разделов: собирать DOM в `UI.stage()`, не вызывать
  `host.innerHTML = ""`, менять состояние через module-level переменные и
  перерисовываться молча (`render(main, state, true)`), идентификаторы читать из
  `dataset` в момент клика.

## Фон и анимации

- За интерфейсом — canvas «сеть коллекторов» (узлы-колодцы, трубы, бегущие импульсы).
  Скорость и отключение задаются в **«Система → Обзор» → карточка «Фон и анимации»**:
  `Выкл` (останавливает отрисовку канваса и прячет размытые пятна, экономит батарею),
  `Медленно` (0.35×), `Обычный` (1×), `Быстро` (2×), плюс тумблер «бегущие импульсы».
  То же доступно из палитры команд (`Ctrl+K` → группа «Фон»). Настройка хранится в
  браузере (`mc_bg_speed`, `mc_bg_pulses`), применяется мгновенно, без перезагрузки.
- Системный `prefers-reduced-motion` отключает движения фона и анимации интерфейса.

## Надёжность данных и реплей

- **Перезапуск круга реплея (`Заново с января`, автоперезапуск `SIM_LOOP`) не удаляет
  человеческие данные**: решения диспетчера, заявки, которых коснулся человек
  (назначены/в работе/выполнены/отменены, созданы вручную или «профилактикой»,
  с датой выезда/исполнителем/комментарием), и журнал аудита сохраняются. Удаляются
  только прогнозы (пересчитываются) и необработанные предложения автоформирования.
  Подтверждающий текст есть в диалоге перезапуска и на карточке часов.
- **Раздел «Заявки» не фильтруется ползунком направления в шапке** — у доски свой
  фильтр «все направления», поэтому заявки никогда не «пропадают» из-за
  переключённого направления.
- Восстановление потерянных ранее заявок из журнала аудита:
  `tests/inspect_audit_tickets.py` (что известно) и
  `tests/restore_tickets_from_audit.py [--apply]` (последнее зафиксированное
  состояние: статус, автор, комментарий, время; неизвестные поля не выдумываются).
- Инвариант проверяется живьём: `tests/check_replay_safety.py`.

## Граф систем, недельный риск и уведомления

- **Раскраска графа = выбранное направление.** Ползунок направлений в шапке
  перекрашивает узлы: цвет — `P(событие ≤ 7 дней)` по этому направлению
  (`node.risk7d[task]` из `GET /objects/graph`), а не «максимум по всем
  направлениям». Объекты без недельных прогнозов — «полые» точки
  (чужой риск не подставляется), это же видно в подсказке и легенде.
- **Подписи объектов** не накладываются друг на друга: подпись ставится в первое
  свободное место (снизу → сверху → справа), при нехватке места скрывается
  (остаётся в подсказке при наведении). Есть галочка «подписи объектов».
- **Клик по объекту** на графе открывает карточку объекта: статистика, риски по
  всем направлениям, датчики, заявки и **график работ по объекту**.
- **Тренд риска** (дашборд) — переключатели горизонта 24ч / 3д / 7д / 30д и
  «максимум»; ось в процентах «круглыми» делениями, потолок ровно **100%**
  (шкала никогда не уходит выше, даже если риск достиг 1.0).
- **Уведомления** приходят только при `P(≤7 дней) ≥ 0.2` и не чаще одного раза в
  **12 часов** на датчик; клик по уведомлению (и по строке панели) ведёт на **сам
  объект** — карточку со рисками по всем направлениям, датчиками, заявками и
  графиком работ по объекту. Для приёмки/демо есть `Notify.demo(n)` — показать
  n уведомлений по актуальным топ-рискам.
- **Кнопка «Сформировать заявки»** (пульт, план ТО, палитра команд) сначала
  показывает диалог с параметрами автоформирования из `GET /maintenance/summary`
  (`auto.min_risk`, `auto.top_k`): какие каналы попадут, сколько максимум за запуск,
  что дубли не создаются; после выполнения — тост с числом созданных заявок и
  ссылкой на раздел «Заявки» (`UI.autoGenerate`).
- **Канбан заявок**: число колонок задаётся переменной `--cols`, поэтому при снятии
  галочки «показывать отменённые» оставшиеся 4 колонки занимают освободившуюся
  ширину. Галочки/переключатели в строке фильтров больше не растягиваются
  (правило `.toolrow > input|select` — только прямые дети).
- **Индикаторы-ползунки** (`.seg-ind`, `.chip-ind`, `.nav-ind`) позиционируются по
  фактической ширине активной кнопки: помечены `data-keep` (мягкое обновление их не
  трогает), пересчитываются через `ResizeObserver` + `FX.refreshSliders()` после
  вставки раздела в DOM, а первая установка идёт без анимации — индикатор больше не
  «проезжает» от левого края и не пропадает после переключения.
- **Дата выезда**: в карточке заявки есть поле «дата выезда» + «сохранить дату»;
  в диалоге решения «Профилактика» — календарь (дата сразу попадает в заявку).
- **График обслуживания** (раздел «План ТО») — группировка заявок по дате выезда
  с фильтром 7/30/90 дней, «только открытые», экспортом CSV и переходом в карточку
  заявки; отсчёт от сим-времени.

## Производительность и доступность

- Один `#pagebox` на экран, скелетоны при навигации, живые обновления без мигания
  (`silent`-рендер), кэш GET с дедупликацией параллельных запросов.
- `prefers-reduced-motion` отключает анимации; клавиатура: `Ctrl+K` — палитра,
  `1..4` — направления, `[` — свернуть меню, `Esc` — закрыть оверлеи.
- Заголовок `X-Request-ID` каждого ответа показывается в деталях аудита —
  сквозная трассировка UI → API → лог.
